# Phant0m C4llb4ck Writeup

## Summary
The challenge is a .NET reverse engineering task involving two stages:
1. `Phantom.Callback.dll` (Loader):
   - Reads custom assembly metadata `missed.calls` (`1bbca4d59f20673e`) and `resource.name` (`trace.return`).
   - Decrypts the embedded resource `trace.return` using a pseudo-random generator `N` (SplitMix64 variant) and rotation `R`.
   - The decrypted payload is loaded dynamically via `Assembly.Load(..).EntryPoint.Invoke(..)`.

2. Decrypted Core Assembly:
   - Takes input `s` of length 41 with format `e0f{...}`.
   - Computes an exception selector `(s[0]*3 + s[1]*5 + s[2]*7 + s[3]*11) & 3` which yields `2` for `e0f{`.
   - Throws exception `R(2)` which is caught and filters to index `2`.
   - The 36 inner characters are scrambled into a 40-byte buffer (with suffix `0xdeadc0de`) and packed into 6 64-bit lanes (with lane 5 = `0x566715150d283122`).
   - The 6 lanes undergo a sequence of 104 reversible VM operations (`A`, `B`, `C`, `D`, `E`, `F`) generated by `Tape()` and `Seed()` based on `trace.*` metadata attributes.
   - The output is compared against `Target(2)` which unmasks a static array `V`.

3. Solution:
   - Invert all 6 VM operations (Add, XOR, Rotate, Multiply, Swap, Feistel step).
   - Invert the permutation and unmask the 36 inner characters.
   - Recover the flag: `e0f{d0tn3t_m3t4d4t4_h1d3s_1n_pl41n_s1ght}`.
